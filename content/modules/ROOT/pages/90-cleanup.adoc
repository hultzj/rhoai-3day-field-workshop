= Cleanup
:navtitle: Cleanup

Run only what matches how far you got. Each block is safe to re-run.

== Participant cleanup

Remove what you created in the labs, from the Web Terminal. First look at what will go:

[source,bash,role="execute",subs="attributes+"]
----
oc get project {gpu_namespace} {model_namespace} --ignore-not-found
oc get modelregistries.modelregistry.opendatahub.io -n {registry_namespace} --ignore-not-found
oc get gpucluster,nvidiadriver --ignore-not-found
oc get nodefeaturediscovery -n openshift-nfd --ignore-not-found
----

Expected result: whichever exist of: projects `{gpu_namespace}` and `{model_namespace}` (`Active`),
the `{registry_name}` registry (`AVAILABLE True`), `gpucluster.nvidia.com/gpu-cluster` and
`nvidiadriver.nvidia.com/gpu-driver` (`ready`), and `nfd-instance`.

If you did Day 3, remove its projects and MLflow first. Look first:

[source,bash,role="execute",subs="attributes+"]
----
oc get project ws-agent ws-eval ws-guard --ignore-not-found
oc get mlflows.mlflow.opendatahub.io --ignore-not-found
oc get networkpolicy -n {model_namespace} --ignore-not-found
----

Expected result: whichever exist of: the projects `ws-agent`, `ws-eval` and `ws-guard` (`Active`),
the `mlflow` tracking server (`AVAILABLE True`, version `3.14.0`), and the NetworkPolicy
`{model_name}-ingress`.

[source,bash,role="execute",subs="attributes+"]
----
oc delete project ws-agent ws-eval ws-guard --ignore-not-found --wait=true
oc delete networkpolicy {model_name}-ingress -n {model_namespace} --ignore-not-found
oc delete mlflows.mlflow.opendatahub.io mlflow --ignore-not-found --wait=true

oc get project ws-agent ws-eval ws-guard --ignore-not-found

Expected result: the projects, the NetworkPolicy and the tracking server are deleted. Evaluation
results go with the `ws-eval` project; traces do not go with `ws-agent` (MLflow stores them on its
own volume, keyed by workspace name) but with the tracking server and its volume, `default-dsc patched` sets MLflow back to `Removed` (its pods and
volume disappear within a minute), and the last command prints nothing.

WARNING: Deleting the project in which your Web Terminal runs closes the terminal. The Web Terminal
runs in its own project (`openshift-terminal` by default), so the commands above do not touch it.

== Facilitator teardown

Only whoever deployed the environment removes it, from a cluster-admin shell in a checkout of this
repository. First look at what the teardown will delete: every Application listed, along with the
operators and namespaces it created.

[source,bash,subs="attributes+"]
----
make -C automation status
oc get namespace {showroom_namespace} nvidia-gpu-operator openshift-nfd --ignore-not-found
----

Then delete it and confirm the Showroom namespace is gone:

[source,bash,subs="attributes+"]
----
make -C automation teardown
oc get namespace {showroom_namespace} --ignore-not-found
----

The last command prints nothing once deletion completes. Teardown removes the Applications, then
exactly the operators (CSVs) its own Subscriptions installed (NFD, GPU Operator, RHCL, Web Terminal;
recorded in the ConfigMap `rhoai-3day-field-workshop-installed-csvs` in `openshift-gitops` just
before), then the namespaces it created. If it stops
part way, run it again: each step is safe to repeat. It also removes the dependency operators OLM
installed together with them (for RHCL on a fresh cluster: Authorino, Limitador and the DNS operator;
for the Web Terminal: DevWorkspace), recognised by package, OLM's generated Subscription name and a
creation time within three minutes after the lab's Subscription; a dependency that already existed,
such as a standalone Authorino, stays, and so does any other operator installed meanwhile. A dependency left
behind auto-upgrades and can make the next bootstrap unresolvable (`ResolutionFailed`). CRDs stay.
List what remains:

[source,bash]
----
oc get csv -A --no-headers | awk '{print $1, $2}' | sort -u -k2,2 | grep -E 'nfd|gpu-operator-certified|rhcl-operator|web-terminal|devworkspace|authorino|limitador|dns-operator'
----

Delete a dependency's CSV and Subscription only if nothing else on the cluster uses it.

To reuse the cluster for another class, also remove the labels NFD left on the nodes, so Module 1
starts from an unrecognised GPU again. Look first, then remove:

[source,bash]
----
oc get nodes -o json | jq -r '.items[] | .metadata.name as $n | .metadata.labels | keys[] | select(startswith("feature.node.kubernetes.io/")) | "\($n) \(.)"' | sort | uniq | head
for n in $(oc get nodes -o name); do
  l=$(oc get "$n" -o json | jq -r '.metadata.labels | keys[] | select(startswith("feature.node.kubernetes.io/pci-")) | . + "-"')
  [ -z "$l" ] || oc label "$n" $l
done
----
